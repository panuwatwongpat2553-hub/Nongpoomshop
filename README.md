# Nongpoom Shop — Backend

เซิร์ฟเวอร์จริงสำหรับร้าน: สมัคร/เข้าสู่ระบบ, สินค้า, กระเป๋าเครดิต, สั่งซื้อ, คูปอง, เติมเงิน, แจ้งปัญหา และระบบผู้ดูแล
ไม่ต้องติดตั้งแพ็กเกจเพิ่ม ใช้ Node.js 22 ขึ้นไปอย่างเดียว (ฐานข้อมูล SQLite ในตัว)

## การเติมเงินจริงในเวอร์ชันนี้
- ลูกค้าสมัคร/เข้าสู่ระบบกับ API จริง, สร้างรายการเติมเงิน, เห็นบัญชีรับเงิน, แนบสลิป และดูสถานะได้
- **ยังเป็นการโอนเงินแล้วให้ผู้ดูแลตรวจสลิป/ยอดเงินจริงก่อนอนุมัติ** ไม่ใช่ payment gateway อัตโนมัติ
- ห้ามอนุมัติจากรูปสลิปอย่างเดียว ควรตรวจยอดเข้าบัญชีจริงก่อนทุกครั้ง
- TrueMoney และ KBank ต้องตั้งค่า `PAY_TRUEMONEY` / `PAY_KBANK` ให้ถูกต้องก่อนเปิดรับโอน
- การรับชำระอัตโนมัติต้องทำสัญญา/เปิดใช้ API กับผู้ให้บริการ และปรับ webhook ให้ตรงเอกสารผู้ให้บริการก่อนเปิดใช้งาน

## เริ่มใช้งาน
```bash
export APP_SECRET="$(openssl rand -hex 32)"   # ต้องตั้ง และเก็บเป็นความลับ
export ADMIN_USER=boss ADMIN_PASS='รหัสผ่านยาว10ตัวขึ้นไป'   # สร้างผู้ดูแลคนแรกตอนเริ่ม
export PAY_KBANK='ชื่อบัญชี|เลขบัญชี' PAY_TRUEMONEY='ชื่อ|เบอร์วอลเล็ต'   # บัญชีรับเงินที่ลูกค้าจะเห็น
export WEBHOOK_SECRET="$(openssl rand -hex 32)"  # ถ้าจะรับ callback จากผู้ให้บริการชำระเงิน
node server.js          # เปิดที่พอร์ต 3000
node test.mjs           # ทดสอบ 72 ข้อ (ผ่านหมดตอนส่งมอบ)
```
ข้อมูลอยู่ในไฟล์ `shop.db` (สำรองไฟล์นี้เป็นประจำ)

## สิ่งที่ระบบรับประกัน (ผ่านการทดสอบ)
- เครดิตทุกการเปลี่ยนแปลงถูกบันทึกใน ledger และติดลบไม่ได้
- ซื้อซ้ำไอดีเดียวกันไม่ได้ ซื้อไม่ผ่านจะไม่ตัดเครดิตและไม่ปิดขาย
- อนุมัติเติมเงินซ้ำ/ส่ง webhook ซ้ำ ไม่เพิ่มเครดิตสองรอบ
- ข้อมูลล็อกอินไอดีเกมไม่อยู่ในรายการสินค้าสาธารณะ ผู้ซื้อเห็นหลังซื้อเท่านั้น
- ผู้ดูแลปรับเครดิตได้ต้องใส่เหตุผล และมีบันทึกทุกครั้ง ไม่มี API คืนเงิน (เครดิตขอคืนไม่ได้)
- รหัสผ่านเก็บแบบ scrypt, จำกัดการเดารหัส, ตรวจสิทธิ์ทุกคำขอฝั่งเซิร์ฟเวอร์

## API หลัก (Authorization: Bearer <token>)
ลูกค้า: `POST /api/register` `POST /api/login` `GET /api/me` `GET /api/products` `POST /api/orders {product_id, coupon?}` `GET /api/orders` `POST /api/topups {method: truemoney|kbank, amount, slip}` (**slip บังคับ**) `GET /api/payinfo` `GET /api/topups` `POST/GET /api/tickets`
ผู้ดูแล (role admin): `/api/admin/` stats, products (CRUD + ข้อมูลไอดี), coupons, members (+`members/:id` ข้อมูลทั้งหมดของลูกค้า, `/adjust`, `/password`, `/role`), ledger/:id, orders, topups (+approve/reject), tickets (+reply), audit

เพิ่มใหม่: `POST /api/coupon-check {product_id, code}` · `POST /api/me/password {current, next}` · `GET/POST /api/reviews`

## สิ่งที่ยังต้องทำก่อนเปิดขายจริง
1. **ต่อผู้ให้บริการรับชำระเงินจริง** (PromptPay/ทรูมันนี่ผ่านเจ้าที่ออก API ให้ร้านค้า) แล้วให้เขาเรียก `POST /api/webhook/payment` ด้วย body `{ref, amount, status:"paid"}` และ header `x-signature` = HMAC-SHA256 ของ body ด้วย `WEBHOOK_SECRET`
   ถ้าผู้ให้บริการใช้รูปแบบ/ลายเซ็นต่างจากนี้ ต้องปรับฟังก์ชัน webhook ให้ตรงกับเอกสารของเขา จนกว่าจะต่อเสร็จ ผู้ดูแลต้องกดอนุมัติเติมเงินเองหลังตรวจยอดเข้าบัญชี
2. **HTTPS** วางหลัง reverse proxy (Caddy/Nginx/Cloudflare) ห้ามเปิด HTTP ตรง ๆ
3. ~~ยืนยัน OTP ทาง SMS~~ ตัดออกแล้ว (v8): สมัครด้วยชื่อผู้ใช้ เบอร์โทร และรหัสผ่านแล้วใช้งานได้ทันที ไม่ยืนยันเบอร์
4. ~~เชื่อมหน้าเว็บกับ API~~ เสร็จแล้ว: `public/index.html` ใช้ API จริงทั้งสมัคร/ล็อกอิน สินค้า ตะกร้า/สั่งซื้อ คูปอง เติมเงิน+สลิป คำสั่งซื้อ(แสดงข้อมูลไอดีหลังซื้อ) แจ้งปัญหา รีวิว(เฉพาะผู้ซื้อ) เปลี่ยนรหัสผ่าน; ผู้ดูแลจัดการร้านที่ `/admin.html` (ปุ่ม "จัดการร้าน" ในหน้าร้านจะแสดงเฉพาะแอดมิน). คูปองใช้กับไอดีราคาสูงสุดในตะกร้า 1 รายการต่อครั้ง. ยังไม่มีเปลี่ยนชื่อที่แสดง (ใช้ชื่อผู้ใช้ตอนสมัคร)
5. ข้อความนโยบายและ PDPA ให้ผู้เชี่ยวชาญตรวจ และเก็บเบอร์โทรเท่าที่จำเป็น


## v3: ความน่าเชื่อถือหน้าร้าน
- `GET /api/public/stats` (ไอดีพร้อมขาย ออเดอร์ สมาชิก คะแนนรีวิวเฉลี่ย) และ `GET /api/recent-sales` (ขายล่าสุด ชื่อผู้ซื้อถูกปิดบังเหลือ 2 ตัวแรก ไม่มีข้อมูลไอดี) เป็นตัวเลขจริงจากฐานข้อมูล ไม่ต้องล็อกอิน
- หน้าแรกแสดงสถิติและรายการขายล่าสุดจากสองเส้นทางนี้ รีเฟรชทุก 60 วินาที
- หลังซื้อสำเร็จ หน้าเว็บเปิดข้อมูลไอดีให้ทันที ไม่ต้องกดหาในประวัติคำสั่งซื้อ
- Dockerfile ไม่มีบรรทัด `VOLUME` (Railway ไม่รองรับ) ให้สร้าง Volume ที่ mount path `/data` ในหน้า Railway แทน

## v4: แจ้งเตือน LINE ให้เจ้าของร้าน
ตั้งตัวแปร `LINE_CHANNEL_TOKEN` (Channel access token แบบ long-lived ของ Messaging API) และ `LINE_ADMIN_USER_ID` (User ID ของคุณ) ระบบจะส่งข้อความเข้า LINE เมื่อมีสลิปเติมเงินใหม่ (ต้องรีบตรวจ) และเมื่อมีเรื่องแจ้งปัญหาใหม่ ถ้าไม่ตั้งตัวแปรสองตัวนี้ ระบบจะไม่ส่งอะไรและทำงานตามปกติ
- ไม่แจ้งทุกออเดอร์ เพราะแผนฟรีของ LINE ส่งได้จำกัดต่อเดือน มีเพดานในระบบ `LINE_MAX_PER_MONTH` (ค่าเริ่มต้น 150) เกินแล้วหยุดแจ้งจนต้นเดือนถัดไป การสั่งซื้อและเติมเงินไม่ได้รับผลกระทบ
- ถ้า LINE ล่มหรือโทเค็นผิด ระบบแค่บันทึก log ไม่ทำให้ลูกค้าใช้งานไม่ได้

## v7: เอาระบบจองผ่อนออก
- ลบเมนู ปุ่ม หน้าจอ เส้นทาง API และแท็บแอดมินของระบบผ่อนทั้งหมด การซื้อกลับเป็นแบบจ่ายเต็มจากเครดิตอย่างเดียว
- เมื่อเริ่มทำงานครั้งแรกหลังอัปเดต ระบบจะตรวจหาแผนผ่อนที่ยังค้างอยู่ **คืนเครดิตให้สมาชิกเต็มจำนวน (รวมค่าจอง)** และปล่อยไอดีที่ถูกล็อกกลับไปขาย แล้วไม่ทำอะไรอีก
- ตารางข้อมูลผ่อนเดิมในฐานข้อมูลไม่ถูกลบ (เก็บเป็นประวัติ) ไม่มีผลต่อการทำงาน

## v8: เอาขั้นตอน OTP/SMS ออกจากหน้าสมัคร
- ตัดขั้น "ยืนยัน OTP" และโค้ดเก่าที่ค้างอยู่ออกทั้งหมด หน้าสมัครเหลือ 2 ขั้น (กรอกข้อมูล > เสร็จสิ้น) สมัครแล้วเข้าสู่ระบบทันที เบอร์โทรยังเก็บไว้เป็นข้อมูลติดต่อแต่ไม่ได้ยืนยัน


## v11: ผู้ดูแลหลายคน, จัดการสมาชิก, บังคับสลิป
- **เจ้าของร้าน** = บัญชี `ADMIN_USER` (หรือแอดมินคนแรก) ตั้ง/ถอดผู้ดูแลได้ที่หน้าแอดมิน > สมาชิก > ปุ่ม "ตั้งเป็นผู้ดูแล" เจ้าของร้านถูกถอดไม่ได้ ผู้ดูแลคนอื่นตั้งผู้ดูแลเพิ่มไม่ได้ ผู้ดูแลทั่วไปรีเซ็ตรหัสของผู้ดูแลคนอื่นไม่ได้ (กันยึดบัญชี) คนที่เพิ่งถูกตั้ง/ถอดต้องล็อกอินใหม่
- **ดูข้อมูลลูกค้า**: ปุ่ม "ดูข้อมูล" แสดงชื่อผู้ใช้ เบอร์โทร สิทธิ์ เครดิต เวลาสมัคร/เข้าใช้ คำสั่งซื้อ (พร้อมข้อมูลไอดีที่ส่งมอบ) เติมเงิน ประวัติเครดิต และเรื่องที่แจ้ง
- **รหัสผ่าน**: ระบบเก็บเป็น hash ทางเดียว (scrypt) จึง *ดูรหัสเดิมไม่ได้* โดยตั้งใจ (ถ้าเก็บให้ดูได้ ข้อมูลรั่วครั้งเดียวรหัสลูกค้าหลุดทั้งหมด และลูกค้ามักใช้รหัสเดียวกันหลายเว็บ) ให้กดปุ่ม "รหัสผ่าน" เพื่อตั้งรหัสใหม่ให้ลูกค้า (พิมพ์เองหรือสุ่ม แสดงครั้งเดียว) อุปกรณ์ที่ล็อกอินค้างจะถูกออกจากระบบทันที การเปลี่ยนรหัสเองของลูกค้าก็เช่นกัน
- **ปรับเครดิต**: เพิ่ม / หัก / **ตั้งยอดเป็น...** ต้องใส่เหตุผลเสมอ ลงบันทึกในประวัติเครดิต เครดิตติดลบไม่ได้
- **ประวัติการทำงาน** (เมนูใหม่): บันทึกว่าผู้ดูแลคนไหนปรับเครดิต/รีเซ็ตรหัส/ตั้งผู้ดูแล/อนุมัติ-ปฏิเสธเติมเงิน เมื่อไร
- **เติมเงินต้องมีสลิปทุกครั้ง**: `POST /api/topups` ต้องส่งรูปสลิปมาในคำขอเดียวกัน ไม่มีสลิป/ไฟล์ไม่ใช่รูปจริง (ตรวจจากโครงไฟล์) = ไม่สร้างรายการ สลิปรูปเดิมใช้ซ้ำไม่ได้ ค้างรอตรวจได้ไม่เกิน 5 รายการ และอนุมัติรายการที่ไม่มีสลิปไม่ได้ (รวมทาง webhook) รายการเก่าที่ค้างโดยไม่มีสลิปจะถูกปฏิเสธอัตโนมัติตอนเริ่มระบบ (ไม่เคยเพิ่มเครดิต) ตัด endpoint แนบสลิปแยกออกแล้ว

| ลิงก์แนะนำเพื่อน | `/?ref=รหัส` เปิดหน้าสมัครพร้อมกรอกรหัสให้ ช่องรหัสแก้ได้ ส่วนลิงก์ของตัวเองและสถิติอยู่ใน "บัญชีของฉัน" |
